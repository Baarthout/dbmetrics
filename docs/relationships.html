Conceptual relationship map

The CRM schema follows a hub-and-spoke model. Accounts operate as the hub while sales, marketing, and support activities are spokes that reference the account surrogate key. This approach ensures downstream reporting can stitch every interaction back to the company level.

Account-centric hub

  • One account to many contacts.
  • One account to many opportunities.
  • One account to many support_cases.

Opportunity pipeline

  • Each opportunity belongs to one account.
  • Each order_header is optionally linked to an opportunity.
  • order_lines require an order_header and product.

Engagement telemetry

  • activities optionally reference an account and contact.
  • Every activity_outcome references exactly one activity.
  • Marketing campaign_responses join via contact_id.

Customer health

  • health_snapshots provide periodic scores per account.
  • success_plans link accounts to key playbooks.
  • support_cases feed health scoring inputs.

Common join paths

Use the following patterns to build analytics models and operational reports. All joins are inner unless noted.

Use case Primary tables Join logic Notes
Pipeline velocity opportunities → stages opportunities.stage = stages.name AND stages.stage_type = 'opportunity' Filter opportunities by created_at date for cohorts.
Bookings attribution order_headers → opportunities → accounts order_headers.opportunity_id = opportunities.opportunity_id → accounts.account_id Use left join from order_headers to opportunities for legacy deals.
Contact engagement activities → contacts → accounts activities.contact_id = contacts.contact_id → contacts.account_id Activities without contacts roll up through account_id only.
Support responsiveness support_cases → users support_cases.owner_user_id = users.user_id Join to stages for additional SLA grouping.
Customer health trend health_snapshots → accounts → support_cases health_snapshots.account_id = accounts.account_id → support_cases.account_id Aggregate support cases by opened_at week.
sql example

Sample modeling query

The query below demonstrates how analytics engineers can build a fact table representing the opportunity funnel with associated account metadata.

Opportunity fact view

WITH base AS (
  SELECT
    o.opportunity_id,
    o.account_id,
    o.stage,
    s.order_rank AS stage_order,
    o.amount,
    o.close_date,
    a.industry,
    a.lifecycle_stage,
    a.annual_revenue
  FROM crm.opportunities AS o
  JOIN crm.accounts AS a ON a.account_id = o.account_id
  JOIN crm.stages AS s
    ON s.name = o.stage
   AND s.stage_type = 'opportunity'
)
SELECT
  base.account_id,
  a.name AS account_name,
  base.opportunity_id,
  base.stage,
  base.stage_order,
  base.amount,
  base.close_date,
  base.industry,
  base.lifecycle_stage,
  base.annual_revenue,
  SUM(base.amount) OVER (PARTITION BY base.stage) AS stage_total_amount
FROM base
JOIN crm.accounts AS a ON a.account_id = base.account_id;

Materialize the result as a view in the analytics warehouse to feed BI dashboards. Partitioning the window function by stage yields the total pipeline amount per stage without additional aggregation steps.
